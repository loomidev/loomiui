This release fills a batch of gaps found while building a real app on LoomiUI: form fields can show errors sent back by a server, menus, pagination, empty states and tabs can be real links, hand-written tables get footers and column options, and there's a stylesheet to stop the page jumping before components load.

## Form fields: show an error from the server

Every form control takes a new `error` attribute. The field renders in its error state with the message underneath as soon as the page loads, which is what you want after a form is submitted and rejected, or after a check the component can't do itself (a username that's taken).

```html
<loomi-input name="phone" label="Phone number" value="12" error="Enter a 10-digit phone number"></loomi-input>
```

The message is linked to the field for screen readers, and it clears as soon as the user changes the value. It works on `loomi-input`, `loomi-password`, `loomi-textarea`, `loomi-select`, `loomi-number` and `loomi-filepicker`.

## Links where links belong

- **Menu items:** `loomi-dropmenu-item` takes `href` (plus `target` and `rel`). The whole row is the link, icon and padding included, so there are no dead spots, and open-in-new-tab works. Profile menu rows get this too.
- **Pagination:** `href-template="/orders?page={page}"` makes every page control a real link, so pages can be opened in new tabs, crawled, and used without JavaScript. `loomi-page-change` still fires first, and you can cancel it to handle routing yourself.
- **Empty state:** `button-href` turns the action into a link ("Start shopping"). Anything you put inside the component now shows next to the button, so a second action is easy.
- **Tabs:** a tab with `url` now renders a real link.

## Tabs that scroll instead of wrapping

`overflow="scroll"` on `loomi-tabs` keeps the headings on one line. When there are more than fit, the row scrolls sideways, fades at the edges and shows arrow buttons, and the active tab is scrolled into view. Together with `url` tabs, this makes a row of category filter chips.

```html
<loomi-tabs tab-style="pills" overflow="scroll">
  <loomi-tab label="All" url="/shop" active></loomi-tab>
  <loomi-tab label="Grains" url="/shop?c=grains"></loomi-tab>
</loomi-tabs>
```

## Hand-written tables: footers and column options

Rows written in a `<template>` live inside the table's shadow DOM, out of reach of page CSS. Now:

- `<template slot="footer">` renders as a `<tfoot>`, for totals.
- Header cells accept `align="end"`, `nowrap` and `width`, applied to the whole column.
- Built-in classes for cells: `align-end`, `align-center`, `nowrap`, `tabular` and `sr-only`. Links in cells are styled.
- For anything else, style `::part(row)`, `::part(header-cell)`, `::part(cell)` and `::part(footer-cell)`.

## Before components load

The new optional `@loomidev/theme/undefined.css` hides `loomi-*` elements until their script has loaded and reserves about the right amount of space for each, so the page no longer flashes bare text or shifts when components appear. Add it in `<head>`.

## Smaller fixes

- Icons: the names Heroicons uses (`squares-2x2`, `h1`) now work alongside LoomiUI's hyphenated ones (`squares-2-x-2`), and an unknown icon name logs a warning instead of silently showing nothing.
- `loomi-number`: the floating label uses the full field width, so "Quantity" no longer shrinks to "Qu…" in narrow fields.
- Data grid: columns can configure the always-open input (`inputType`, `inputMode`, `placeholder`, `autocomplete`) and flag invalid cells with `invalid(row)`.

## Worth knowing

- `loomi-pagination` now updates `page` after `loomi-page-change` fires, not before.
- Content placed inside `loomi-empty-state` now shows below the message even when the illustration is on. Before, it only showed with `show-image="false"`.

## Upgrading

```sh
npm install @loomidev/components@^0.15.0
```

If you install components one by one, change each `@loomidev/*` dependency to `^0.15.0`. Because these are 0.x versions, a `^0.14.0` range won't pick up this release on its own.

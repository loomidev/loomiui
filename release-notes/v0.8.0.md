This release gives every component the same set of sizes. Before, each component had its own names: a modal was `large`, a card was `sm`, a spinner was `md`, and `medium` was smaller than the default in some components and bigger in others. Now every size means the same thing wherever you use it. This is a breaking change, so most apps will need a few small edits.

## One size scale for everything

Every `size` attribute, plus `blur-size`, `image-size`, `icon-size` and `avatar-size`, now takes one of seven names, from smallest to largest:

`tiny`, `small`, `regular`, `medium`, `big`, `huge`, `omg`

`regular` is the default everywhere. If you pass a name a component doesn't support, it uses `regular` rather than breaking.

## What you need to change

### Renamed sizes

The old names are gone, with no aliases, so update any of these you use:

| Component               | Attribute    | Old → new                                                            |
| ----------------------- | ------------ | -------------------------------------------------------------------- |
| modal                   | `size`       | `medium` → `regular` (default), `large` → `big`, `xl` → `huge`       |
| modal                   | `blur-size`  | `medium` → `regular` (default), `large` → `big`, `xl` → `huge`       |
| card                    | `size`       | `default` → `regular`, `sm` → `small`                                |
| drawer                  | `size`       | `medium` → `regular` (default), `large` → `big`                      |
| empty-state             | `image-size` | `medium` → `regular` (default), `large` → `big`, `xl` → `huge`       |
| side-nav                | `icon-size`  | `large` → `big`                                                      |
| spinner                 | `size`       | `small` → `regular` (default), `xl` → `huge`; `sm`/`md`/`lg` removed |
| bell, otp, rating       | `size`       | `small` → `regular` (default)                                        |
| progress circle and arc | `size`       | `medium` → `regular` (default), `large` → `huge`                     |

### Form fields are a little shorter by default

Input, select, number, password, autocomplete, countries, tag input, the time and timezone pickers and the emoji picker now default to `regular`, which is 2.5rem tall. It used to be `medium` at 2.75rem. Fields now line up with a default button. To keep the old height, add `size="medium"`.

### `medium` moved on avatars and floating action buttons

On `<loomi-avatar>` and `<loomi-fab>`, `medium` used to be smaller than the default. It's now one step bigger, as it is everywhere else. The default size itself hasn't changed. If you used `medium` to get a slightly smaller avatar or button, there's no exact match any more: pick `small` (a little smaller than the old `medium`) or `regular` (a little bigger).

| Component | Old `medium` | `small` now | `regular` now (default) | `medium` now |
| --------- | ------------ | ----------- | ----------------------- | ------------ |
| avatar    | 2.5rem       | 2rem        | 3rem                    | 3.5rem       |
| fab       | 3.25rem      | 2.75rem     | 3.75rem                 | 4.25rem      |

### TypeScript

The per-component size types (`LoomiModalSize`, `LoomiAvatarSize`, `LoomiSelectSize` and 22 others) are replaced by a single `LoomiSize` type from `@loomidev/core`. Your editor's autocomplete now suggests the same list of sizes for every component.

## Other changes

- **Menu arrows point at the right thing.** A dropdown menu's arrow can now line up with a specific part of its trigger (`arrowAnchor` on `<loomi-dropmenu>`). The profile menu uses it, so its arrow sits under the chevron rather than the middle of the whole card.

## Upgrading

```sh
npm install @loomidev/components@^0.8.0
```

If you install components one by one, change each `@loomidev/*` dependency to `^0.8.0`. Because these are 0.x versions, a `^0.7.0` range won't pick up this release on its own.

Every package's CHANGELOG has the full list of changes, and the "Sizing" section of the `@loomidev/core` README explains the scale in detail.

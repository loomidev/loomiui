This release adds a spreadsheet-style editing mode to the data grid, makes the one-time-code field easier to correct, and tidies form-field text size on phones and the text editor's insert dialog.

## Data grid: always-open editing

Until now a cell only turned into an input after a double-click. With the new `mode: "always"`, every editable cell shows its input all the time, styled by the grid, so a table behaves like a spreadsheet.

```js
grid.columns = [{ key: "name", label: "Name", editable: true }];
grid.modules = [inlineEditingModule({ mode: "always" })];
```

- **Moving around:** Enter and the down arrow move to the cell below, the up arrow to the cell above, and Tab moves across. Arrow keys typed inside a cell no longer move the grid's own selection.
- **Pasting:** paste several lines, or cells copied from Excel or Google Sheets, and they fill the cells below and to the right. Each filled cell fires `loomi-cell-edit` as if it had been typed.
- **`grid.focusCell(rowIndex, columnKey)`** puts the cursor in a cell, waiting for the grid to render first. It is handy right after you add a row.

The default mode is unchanged.

## One-time code: Backspace steps back in one press

In `<loomi-otp>`, Backspace on a filled box now clears it and moves to the previous box straight away. Before, the first press cleared the digit and you had to press again to move back.

## Smaller fixes

- On phones and tablets, form fields use text of at least 16px, so iOS Safari no longer zooms the page when you tap into a field.
- The text editor's insert image/video/link dialog has its spacing back, and its field icons show up.

## Upgrading

```sh
npm install @loomidev/components@^0.14.0
```

If you install components one by one, change each `@loomidev/*` dependency to `^0.14.0`. Because these are 0.x versions, a `^0.13.0` range won't pick up this release on its own.

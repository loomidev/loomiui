This release makes submit-on-change forms reliable across every LoomiUI form control, and lets a text field submit its unit dropdown as a separate form value.

## Forms see the new value as soon as `change` fires

If you read a form inside a `change` (or `input`) listener, for example to submit it straight away, you could get the previous value. Clicking `+` on a quantity stepper from 1 to 2 and calling `form.requestSubmit()` in the listener sent `1`. The same thing happened when typing in `loomi-input` or `loomi-textarea`, and when ticking `loomi-checkbox` or `loomi-toggle`.

Now every form control updates its form value before it fires `input` or `change`, so this just works:

```js
stepper.addEventListener("change", () => form.requestSubmit());
```

You can remove any `await el.updateComplete` you added to work around this.

## Submit a field's unit with the form

`loomi-input` dropdown affixes can now be submitted with the form. Name them with `prefix-name` or `suffix-name`:

```html
<loomi-input
  name="pack_size"
  value="5"
  numeric
  suffix-options='[{"value":"1","label":"kg"},{"value":"2","label":"g"}]'
  suffix-name="measure_id"
></loomi-input>
<!-- submits pack_size=5 and measure_id=1 -->
```

As the example shows, `prefix-options` and `suffix-options` also accept value and label pairs, so you can submit an id while showing a readable label. A plain list such as `kg|g|lb` still works as before.

## Upgrading

```sh
npm install @loomidev/components@^0.16.0
```

If you install components one by one, change each `@loomidev/*` dependency to `^0.16.0`. Because these are 0.x versions, a `^0.15.0` range won't pick up this release on its own.

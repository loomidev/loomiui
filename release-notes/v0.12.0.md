This release finishes making the date and file pickers behave like the native inputs they replace. A datepicker's value is now always an ISO date, like `<input type="date">`, and the filepicker exposes `files` and `type` like `<input type="file">`. The rest of the form controls also learn to put their label above the field. The datepicker change is breaking if you use a display `format` other than `yyyy-mm-dd`, so read **Breaking changes** before upgrading.

## Datepicker values are ISO dates, like `<input type="date">`

`<loomi-datepicker>`'s `value` used to come back in its display `format`, so a picker showing `22/06/2026` also submitted `22/06/2026`. Now `value`, the `change` event's `detail.value` and the value your form submits are always `yyyy-mm-dd` (`yyyy-mm-dd - yyyy-mm-dd` for a range), exactly like a native date input. `format` only changes what the field shows. If you need the shown text, read `displayValue`.

```js
const picker = document.querySelector('loomi-datepicker[format="dd/mm/yyyy"]');
picker.value; // "2026-06-22"
picker.displayValue; // "22/06/2026"
```

Setting `value` works as before and takes either form. Pickers using the default `yyyy-mm-dd` format behave exactly as they did.

## The filepicker looks like a file input to frameworks

`<loomi-filepicker>` now has a `files` property that returns a `FileList` of the chosen files, and a `type` property that is always `"file"`, just like `<input type="file">`. Framework bindings that treat file inputs specially now work with it. Adding or removing files fires `input` then `change`. Calling `clear()` no longer fires either event, the same as setting `value = ""`.

## Labels above every form control

`label-position="top"` now works on `<loomi-select>`, `<loomi-datepicker>`, `<loomi-timepicker>`, `<loomi-autocomplete>`, `<loomi-tag-input>`, `<loomi-number>` and `<loomi-otp>`, not just the text fields. The label sits above the field, outside its border, and looks exactly like the one on `<loomi-input>`, so a form that mixes controls lines up. Screen readers announce it as the field's name. On `<loomi-otp>`, where `label` used to be hidden, `top` shows it above the boxes.

```html
<loomi-select label="Department" label-position="top" data='[{"label":"Design","value":"design"}]'></loomi-select>
<loomi-datepicker label="Start date" label-position="top"></loomi-datepicker>
<loomi-otp label="Verification code" label-position="top"></loomi-otp>
```

The datepicker and timepicker fields can now be reached with Tab and opened with Enter, Space or the down arrow, like a select.

## Breaking changes

- **`<loomi-datepicker>` with a non-ISO `format`:** anything that reads its `value`, its `change` event's `detail.value`, or its submitted form value now gets `yyyy-mm-dd`. Switch your server or code to parse ISO dates, or read `displayValue` where you want the formatted text.
- **`<loomi-filepicker>` `clear()`:** if you relied on `clear()` firing `input` or `change`, run your handler yourself after calling it.

## Upgrading

```sh
npm install @loomidev/components@^0.12.0
```

If you install components one by one, change each `@loomidev/*` dependency to `^0.12.0`. Because these are 0.x versions, a `^0.11.0` range won't pick up this release on its own.

Every package's CHANGELOG has the full list of changes.

This release makes every Loomi form control behave like the native input, select or textarea it replaces. You can read and set a control's value in code, and listen for `input` and `change`, exactly as you would with a built-in field. That means `v-model`, `x-model` and similar two-way bindings work on the Loomi tags directly, with no wrapper components. A few controls fire their events differently now, so read **Event changes to check** before upgrading.

## Read and set every value in code

Every form control now has a `value` you can both read and set (`checked` for checkboxes, toggles and radios). Setting it updates what the control shows and what the form submits, and it fires no events, just as setting `input.value` doesn't.

```js
const country = document.querySelector("loomi-select");
country.value = "gh"; // shows Ghana, submits "gh", fires nothing
```

What's new:

- `<loomi-select>` has `value`, a comma-joined string when `multiple` is set, plus `values`, an array. Before, you could only change the selection through `selected-value`.
- `<loomi-otp>` has a `value`. Characters its `type` doesn't accept are dropped.
- `<loomi-checkcards>` has `value` and `values`, and changing `selected-value` after the page loads now takes effect.
- `<loomi-datepicker>`, `<loomi-timepicker>` and `<loomi-slider>` already let you read `value`, and now you can set it too. The datepicker accepts `2026-03-14` or a date in its own `format`. The timepicker accepts `3:30PM` or `15:30` and converts to its format. The slider accepts `40`, or `20 - 80` for a range.
- `<loomi-filepicker>` has a `value` that works like a native file input's: it reads `C:\fakepath\report.pdf`, and setting it to `""` clears the selection.
- Setting a radio's `checked` in code unchecks the other radios in its group, as a native radio does.

## Two-way binding in any framework

Each control fires `input` on every edit and `change` when the edit is committed, and the new value is already in place when your listener runs. Checkboxes, toggles and radios also report a `type` (`"checkbox"` or `"radio"`), which tells binding code to use `checked` instead of `value`.

In Vue, write the `type` out on checkbox-like controls:

```vue
<loomi-select v-model="country" :data="countries"></loomi-select>
<loomi-checkbox type="checkbox" v-model="agreed" label="I agree"></loomi-checkbox>
```

The full rules, with the value format for every control, are in the new "Value and events contract" section of the `@loomidev/core` README. Each form control's README links to it.

## Event changes to check

If your code listens for these events, check it still does what you expect:

- **One `input` per keystroke.** Text fields, the number field, autocomplete, tag input, the rich text editor and the slider used to fire `input` twice for each keystroke or drag step. They now fire it once. If you counted events, or had worked around the duplicate, you can drop the workaround.
- **Checkboxes, toggles and radios fire `input` before `change`**, with `checked` already updated. Before, the `input` came through before `checked` had changed.
- **`<loomi-select>` fires `input` before `change` on each pick.** Typing in a searchable select's filter box no longer fires `input` on the select.
- **`<loomi-text-editor>` fires `change` only after an edit.** Before, it fired every time the editor lost focus, even if nothing had changed.
- **`<loomi-number>` fires fewer events.** Leaving the field fires `change`, plus an `input` only if the number had to be clamped to `min` or `max`. A step button at its limit fires nothing.
- **`<loomi-timepicker>` fires only when the time changes.** Picking an hour before a minute, or choosing the same time again, fires nothing.
- **`<loomi-otp>` fires `input` and `change`.** You get `input` on each digit and `change` when focus leaves the boxes. `loomi-verify` still fires when the last box is filled.
- **`<loomi-autocomplete>` fires `change` for typed text** when focus leaves the field, not only when a suggestion is picked.

## Enter submits the form

Pressing Enter in `<loomi-input>`, `<loomi-password>`, `<loomi-number>` or `<loomi-autocomplete>` now submits the form, as it does in a native text field. A sign-in form with an email field, a password field and a `<loomi-button can-submit>` sends when you press Enter in either field. Validation still runs first, and your `submit` listener fires once. `<loomi-otp>` does the same once every box is filled. In `<loomi-autocomplete>`, Enter still picks the highlighted suggestion, and it only submits when nothing is highlighted.

If you added your own Enter-key listener to make this work, remove it, or the form will submit twice. To keep Enter from submitting in a particular field, add `no-implicit-submit`:

```html
<loomi-input name="search" no-implicit-submit></loomi-input>
```

## Smaller downloads

Loomi components now add far less to your app's JavaScript, which matters most on low-end phones and slow networks. `<loomi-button>` drops from about 102 KB to about 8.4 KB, gzipped, with its styles included. Every component that shows icons shrinks by a similar amount.

- **Icons load when they're shown.** Components used to bundle every Heroicon, even on pages that showed none. Now each icon downloads the first time it appears on screen, and it's cached from then on. A component's own built-in icons, such as a clear button or the password eye, still appear immediately.
- **Your bundler can drop what you don't use.** Every package now tells bundlers which of its files have side effects, so unused code is removed.
- **Leaner button styles.** The button's compiled CSS went from 89 KB to 14 KB by including only the colour classes a button can actually use.

Each package's README now lists its size under **Bundle size**.

## Import changes to check

- **Iconsax and Untitled UI icons need one import.** If you use `source="iconsax"` or `source="untitledui"`, or `icon-source` with either set, add this once, anywhere in your app:

  ```js
  import "@loomidev/icons/iconsax";
  import "@loomidev/icons/untitledui";
  ```

  Without it those icons don't render, and the console tells you which import to add. Apps that don't use these sets no longer bundle them, which also removes about 3,800 files from your build output. `<loomi-text-editor>` brings the few icons its toolbar needs, so it needs no import.

- **To load every Heroicon up front**, as before, add `import "@loomidev/icons/all";`. Icons then render with no delay, at a cost of about 73 KB.
- **`getLoomiIcon()` only returns icons that are ready.** An icon that hasn't loaded yet returns `undefined`. Use `hasLoomiIcon(name)` to check whether a name exists, `await loadLoomiIcon(name)` to fetch one, or the `loomiIcon(name)` directive to render one in your own Lit templates.
- **Fewer build files.** Each Heroicon is its own small file in your build output. To bundle each set as one file instead, see "Fewer, bigger icon chunks" in the `@loomidev/icons` README.

## Insert text from your own toolbar

You can now add your own buttons that insert content where the cursor is, for example a maths toolbar that inserts `\frac{a}{b}`.

- `<loomi-text-editor>` has `insertText()`, `insertHTML()` and `getSelection()`. If clicking your button moved focus away, the editor puts the cursor back where it was before inserting.
- Add buttons to the editor's own toolbar with the `customTools` property. They look and behave like the built-in tools, and clicking one fires a `loomi-tool` event. You can also place your own elements in the toolbar with the `toolbar-start` and `toolbar-end` slots.
- `<loomi-input>`, `<loomi-password>` and `<loomi-textarea>` have `insertText()`, plus `selectionStart`, `selectionEnd` and `setSelectionRange()`, just like native inputs.

Each README has a "custom maths toolbar" example.

## Smaller fixes

- Setting a form control's `value` to a number no longer breaks it. `<loomi-input numeric>` used to go blank and stop updating when given `el.value = 10`. Now every control turns what you assign into text, as native inputs do, so `10` becomes `"10"` and `null` becomes an empty field.
- `<loomi-text-editor>` fires one `input` event per toolbar action. It used to fire two. Its link, image, video and AI tools also keep your selection again: they used to lose it in Chrome, Edge and Safari.
- A `<loomi-select>` keeps the user's choice when its `data` is replaced afterwards. Before, the new options reverted it to the original `selected-value`.
- `<loomi-otp>` keeps its code when you move it to another place on the page.
- `<loomi-timepicker>` shows `15:30` as 3:30 PM in 12-hour mode. Before, it showed an invalid time.
- In menus with `icon-right`, items with and without icons now line up.

## Upgrading

```sh
npm install @loomidev/components@^0.10.0
```

If you install components one by one, change each `@loomidev/*` dependency to `^0.10.0`. Because these are 0.x versions, a `^0.9.0` range won't pick up this release on its own.

Every package's CHANGELOG has the full list of changes.

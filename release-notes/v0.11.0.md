This release is about forms that fit their page. Text fields can now show their label above the box or be named without a visible label, the OTP boxes shrink to fit a phone screen, and a select can take a leading prefix. You also get a promise-based confirm dialog, sortable lists built from your own markup, and richer statistic cards. There are no breaking changes, but a `--loomi-otp-size` you had set on `<loomi-otp>` now takes effect, so check any you've set.

## Labels above the field

`<loomi-input>`, `<loomi-password>` and `<loomi-textarea>` take `label-position="top"`. The label sits above the field, outside its border, the way many sign-up forms are laid out. It's a real `<label>` tied to the field, so clicking it focuses the field and screen readers announce it. The placeholder shows as usual.

```html
<form>
  <loomi-input name="email" type="email" label="Email" label-position="top" placeholder="you@example.com"></loomi-input>
  <loomi-password name="password" label="Password" label-position="top" required></loomi-password>
</form>
```

## Name a field without a visible label

A search box or a field inside a table often has no visible label, but screen readers still need a name for it. `<loomi-input>`, `<loomi-password>` and `<loomi-textarea>` now accept `accessible-label` (or `aria-label`, as on `<loomi-select>`) for that. A visible `label` still takes priority.

```html
<loomi-input accessible-label="Search the docs"></loomi-input>
```

## OTP boxes that fit a phone

Add `fluid` to `<loomi-otp>` and its boxes shrink evenly so the whole row fits its container. Six big boxes fit a 320px screen without spilling over. Where there's room, the boxes stay at their normal `size`. Only the boxes shrink; the gap between them stays the same.

```html
<loomi-otp name="code" total-digits="6" size="big" fluid></loomi-otp>
```

You can also set the box size yourself with `--loomi-otp-size`. Before, the `size` presets overrode a value you set on the element. Now your value wins. The row and the boxes can be restyled with `::part(boxes)` and `::part(box)`.

## A prefix in the select

`<loomi-select>` takes the same leading prefix as `<loomi-input>`: `prefix`, `prefix-icon`, a `prefix` slot and `transparent-prefix`. The label and placeholder start after the prefix.

```html
<loomi-select label="Team" prefix-icon="user-group" data='[{"label":"Design","value":"design"},{"label":"Engineering","value":"eng"}]'></loomi-select>
```

## A confirm dialog you can await

`loomiConfirm()` from `@loomidev/modal` works like `window.confirm()`, but it shows a Loomi modal and returns a promise. The promise resolves to `true` only when OK is clicked, and to `false` on Cancel, Escape, a click on the backdrop or the close icon. If you call it while a dialog is already open, the calls queue up and show one after another.

```js
import { loomiConfirm } from "@loomidev/modal";

if (await loomiConfirm("Delete this invoice?")) deleteInvoice();
```

## Sortable lists from your own markup

`<loomi-sortable>` rows can now be your own HTML: give each direct child a `data-id`. Buttons, links and badges inside a row keep working, and your page styles still apply to them. With `has-handle`, only the handle starts a drag. Without a handle, a drag that starts on a button or link is ignored. Rows can be reordered with a mouse, by touch using the handle, and from the keyboard with Alt+Arrow, or Space to pick up, move and drop. Screen readers announce each move.

The component doesn't move your rows in the page. It fires `loomi-reorder` with the new order of `data-id`s, and you update your list from that. Passing rows through `items` still works.

## Statistic cards with context

`<loomi-statistic>` takes a `description`: a smaller, muted line under the number, such as "Since 1 January". For markup, like a coloured trend arrow, use the `description` slot instead. The description is hidden while the spinner shows. `icon-background` puts the icon in a tinted circle; pair it with `icon-color`.

```html
<loomi-statistic label="Revenue" number="48,200" currency="$" icon-color="#15803d" icon-background="#dcfce7">
  <loomi-icon slot="icon" name="banknotes"></loomi-icon>
  <span slot="description" style="color: #15803d">▲ 8.2% vs last month</span>
</loomi-statistic>
```

## Labels line up across every form control

`<loomi-datepicker>` and `<loomi-timepicker>` used to draw their label above the field, so a form mixing them with `<loomi-input>` or `<loomi-select>` didn't line up. Their labels now sit on the field's top border and float up once a value is chosen, exactly like the other controls. `label-position="inside"` puts the label in the same place in every control too.

Two related height fixes:

- `label-position="inside"` only makes room for a label when there is one. `<loomi-datepicker label-position="inside" placeholder="Start date">` used to be 52px tall next to a 40px input.
- An empty `<loomi-tag-input>` is now the same height as the other controls at every size. It was 4px taller.

## Smaller fixes

- `transparent-prefix="false"` and `transparent-suffix="false"` on `<loomi-input>`, `transparent-prefix="false"` on `<loomi-password>` and `transparent-icons="false"` on `<loomi-number>` now render solid. Before, `"false"` was treated as on.
- `label` on the text fields, `<loomi-autocomplete>` and `<loomi-text-editor>` now shows up as an attribute on the element, so CSS selectors like `[label]` match it.

- In Chrome and Edge, a `<loomi-statistic>` with no icon no longer leaves an empty gap where the icon would be.

## Upgrading

```sh
npm install @loomidev/components@^0.11.0
```

If you install components one by one, change each `@loomidev/*` dependency to `^0.11.0`. Because these are 0.x versions, a `^0.10.0` range won't pick up this release on its own.

Every package's CHANGELOG has the full list of changes.

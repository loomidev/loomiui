This release is about menus and small details you'd notice in everyday screens. Your own CSS now reaches the items in a profile menu, a menu row can hold a full-width button, and notifications with a title get some breathing room. There are no breaking changes, but colored secondary buttons look different, so check any you use.

## Style profile menu items with your own CSS

Items inside `<loomi-profile-menu>` used to be moved inside the component when it loaded, where page styles couldn't reach them. A class on a `<loomi-dropmenu-item>`, or a `::part()` rule for a button inside one, simply didn't apply. The items now stay where you wrote them, so the same CSS works in a profile menu as anywhere else on the page.

## Buttons that fill their row

`<loomi-button>` has a new `full-width` attribute. The button stretches to the width of its container, with the label centered.

It's also how you put a real button in a menu. A menu row holding a full-width button now fills the row, and `hover="false"` stops the row from highlighting behind the button. Before this release, `hover="false"` didn't work: any `hover` attribute left the highlight on. For example, a Sign out button at the bottom of a profile menu:

```html
<loomi-profile-menu name="Alice Wonderland" description="alice@example.com">
  <loomi-dropmenu-item icon="user-circle">Profile</loomi-dropmenu-item>
  <loomi-dropmenu-item icon="cog-6-tooth">Settings</loomi-dropmenu-item>
  <loomi-dropmenu-item divider></loomi-dropmenu-item>
  <loomi-dropmenu-item hover="false">
    <loomi-button full-width outline color="error" size="small">Sign out</loomi-button>
  </loomi-dropmenu-item>
</loomi-profile-menu>
```

## Notifications read more easily

When a notification has both a title and a message, there's now a small gap between them, so a title over a two-line message no longer looks cramped. Notifications with only a message are unchanged. To adjust the gap, set `--loomi-notification-title-gap` (it defaults to `0.25rem`). To style the title or message themselves, use the new `::part(title)` and `::part(message)`.

## Colored secondary buttons stay outlined

A secondary button is an outline: a bordered button with no fill. Until now, adding a `color` to `type="secondary"` turned it into a solid, filled button. It now keeps the outline and uses the color for its border and text, exactly like `outline color="…"`. A plain `type="secondary"` with no color hasn't changed. Split buttons with `type="secondary"` and a `color` change the same way.

If you wanted a solid colored button, drop `type="secondary"`, for example `<loomi-button color="error">`.

`info` and `gray` outline buttons also get their proper colored border and hover shade. They used to fall back to the default gray border.

## Upgrading

```sh
npm install @loomidev/components@^0.9.0
```

If you install components one by one, change each `@loomidev/*` dependency to `^0.9.0`. Because these are 0.x versions, a `^0.8.0` range won't pick up this release on its own.

Every package's CHANGELOG has the full list of changes.
